================================================================================
PROBLEM STATEMENT
================================================================================

Educational institutions operate large, heterogeneous networks with IoT devices,
student endpoints, administrative servers, and academic infrastructure. These
networks face growing threats including ransomware, DDoS attacks, and unauthorized
access — but most institutions lack real-time security monitoring. A Digital Twin
framework allows threat simulation and anomaly detection without risking real
infrastructure.

================================================================================
OBJECTIVES
================================================================================

1. Build a representative educational campus network Digital Twin
2. Ingest and preprocess public cybersecurity datasets (CICIDS2017 / UNSW-NB15)
3. Train ML models for binary anomaly/intrusion detection
4. Map ML predictions to Digital Twin device states
5. Provide a live monitoring dashboard
6. Establish a foundation extensible for future XAI and predictive forecasting

DATA FLOW PIPELINE

┌─────────────────────────────────────────────────────────────────────────────┐
│                        COMPLETE DATA FLOW PIPELINE                          │
└─────────────────────────────────────────────────────────────────────────────┘

STEP 1: DATASET INGESTION
─────────────────────────
Input: CICIDS2017 CSV files in data/raw/
  - 8 files covering Monday-Friday with different attack types
  - Auto-detection: first CSV alphabetically (Friday-WorkingHours-Afternoon-DDos)
  - Manual override: python -m ml.preprocess --filepath <path>

STEP 2: PREPROCESSING (ml/preprocess.py)
────────────────────────────────────────
Input: Raw CSV (692,703 rows × 79 columns for Wednesday file)
Process:
  1. Column name cleanup (strip whitespace)
  2. Label column detection (auto-detects "Label", "label", "Class", etc.)
  3. Drop metadata columns (IP, port, timestamp, protocol - 1 column dropped)
  4. Remove duplicates (107,477 removed)
  5. Handle NaN/Inf values (235 rows dropped)
  6. Binary label normalization:
     - BENIGN, Normal, Legitimate, 0, Background → 0 (BENIGN)
     - Everything else (DoS Hulk, PortScan, etc.) → 1 (ATTACK)
  7. Feature selection: 77 numeric features retained
  8. Train/test split: 80/20 stratified, random_state=42 (NO LEAKAGE)
  9. StandardScaler fitted ONLY on training data
Output:
  - data/processed/X_train.csv (467,992 × 77)
  - data/processed/X_test.csv (116,999 × 77)
  - data/processed/y_train.csv, y_test.csv
  - models/scaler.joblib
  - models/feature_names.joblib

STEP 3: MODEL TRAINING (ml/train.py)
────────────────────────────────────
Input: Processed train/test splits
Models:
  1. Random Forest (Supervised - PRIMARY MVP CLASSIFIER)
     - n_estimators=100, max_depth=None, class_weight="balanced"
     - random_state=42, n_jobs=-1
  2. Isolation Forest (Unsupervised - BASELINE)
     - n_estimators=100, contamination=0.1, random_state=42, n_jobs=-1
Output:
  - models/random_forest.joblib (14 MB)
  - models/isolation_forest.joblib (844 KB)
  - models/training_results.json

STEP 4: MODEL EVALUATION (ml/evaluate.py)
─────────────────────────────────────────
Input: Trained models + test data
Metrics Computed:
  - Accuracy, Precision, Recall, F1-Score, ROC-AUC, False Positive Rate
  - Confusion Matrix (TN, FP, FN, TP)
  - Classification Report
  - ROC Curve (for models with predict_proba)
Output:
  - results/evaluation_results.json
  - results/*_confusion_matrix.png
  - results/*_roc_curve.png

STEP 5: PREDICTION & DIGITAL TWIN INTEGRATION (ml/predict.py)
──────────────────────────────────────────────────────────────
Input: Trained Random Forest + test data + Digital Twin
Process:
  1. FlowPredictor loads model, scaler, feature names
  2. predict_batch() with pre_scaled=True (test data already scaled)
  3. For each flow: predict → attack_probability → risk_score
  4. Deterministic demo IP mapping (row_index % 17 devices)
  4. IP_TO_DEVICE lookup (O(1) dictionary)
  5. DigitalTwinStateManager.record_anomaly()
  6. Device state transition: NORMAL → SUSPICIOUS → UNDER_ATTACK
  7. Event recorded with timestamp, risk, prediction, confidence
Output: Updated Digital Twin state + event history

STEP 6: DIGITAL TWIN STATE MANAGEMENT (digital_twin/state.py)
─────────────────────────────────────────────────────────────
State Transitions (Risk-based):
  - NORMAL (0.00-0.30) → WARNING (0.30-0.60) → SUSPICIOUS (0.60-0.80) → UNDER_ATTACK (0.80-1.00)
  - ML-driven transitions bypass sequential rules (direct assignment)
  - record_anomaly() is primary integration point for ML predictions
  - Event history maintained for dashboard

STEP 7: DASHBOARD VISUALIZATION (dashboard/app.py)

  2. Network Topology - Interactive graph with status highlighting
  3. Device Details - Metadata, neighbors, event history
  4. Security Events - Filterable event table
  5. ML Performance - Metrics from evaluation_results.json + plots
  6. Demo Controls - Run Sample Traffic, Simulate Attack, Reset Twin

STEP 8: CONTROLLED ATTACK SIMULATION (digital_twin/demo.py)

4 Attack Types:

State Machine (Manual Transitions):
  NORMAL → WARNING, SUSPICIOUS, OFFLINE
  WARNING → NORMAL, SUSPICIOUS, UNDER_ATTACK, OFFLINE
  SUSPICIOUS → NORMAL, WARNING, UNDER_ATTACK, OFFLINE
  UNDER_ATTACK → SUSPICIOUS, WARNING, NORMAL, OFFLINE
  OFFLINE → NORMAL
  (ML-driven transitions bypass these rules)

CONTROLLED ATTACK SIMULATION (digital_twin/demo.py)

CLI Interface:

  python -m digital_twin.demo --reset
  python -m digital_twin.demo --list-devices
  python -m digital_twin.demo --list-attacks

Attack Scenarios:
1. port_scan
   - Name: Port Scan
   - Description: Simulated reconnaissance scanning multiple ports
   - Risk Base: 0.65, Confidence Base: 0.75
   - Traffic Pattern: Many small packets, short duration, many destinations

2. ddos
   - Name: DDoS-like Traffic Spike
   - Description: Simulated volumetric attack flooding target
   - Risk Base: 0.85, Confidence Base: 0.90
   - Traffic Pattern: High packet rate, high volume

3. brute_force
   - Name: Brute Force Authentication
   - Description: Simulated repeated login attempts
   - Risk Base: 0.75, Confidence Base: 0.80
   - Traffic Pattern: Repeated connections, SYN flags

4. unauthorized_access
   - Name: Unauthorized Access Attempt
   - Description: Simulated privilege escalation
   - Risk Base: 0.80, Confidence Base: 0.85
   - Traffic Pattern: Anomalous protocol, PSH flags

Synthetic Telemetry Generation:
  - Loads test data (X_test) as base
  - Modifies features per attack type:
    - port_scan: Low packet count, short duration, high packet rate
    - ddos: High packet count, high bytes/packets per second
    - brute_force: Moderate packets, repeated SYN flags
    - unauthorized_access: Moderate packets, PSH flags
  - Adds destination_ip for target device

Pipeline:
  1. Generate synthetic flows
  2. FlowPredictor.predict_batch(pre_scaled=True)
  3. IP_TO_DEVICE lookup
  4. DigitalTwinStateManager.record_anomaly()
  4. Returns summary with attack/normal counts, risk scores, final device state

Reset Function:
  - Iterates all devices, calls mgr.reset_device() if not NORMAL
  - Clears event history (by creating new manager)
